# SwarmGrid

Multi-Agent Path Finding (MAPF) for a warehouse robot fleet: Conflict-Based Search (CBS),
ECBS, prioritized planning, and lifelong windowed replanning on 4-connected grids.
C++17, CMake. The only dependency is vendored [doctest](https://github.com/doctest/doctest) 2.4.11.

> Work in progress. The final README (algorithms, architecture diagram, benchmarks, demo, limitations)
> gets written at the end, with measured numbers only.

## Live dashboard

**https://tabish2786.github.io/SwarmGrid/** (works on any laptop or phone browser)

It draws the warehouse, the robots and their paths exactly as the C++ planner computed them:
the same 10 robots planned independently (with collisions), with prioritized planning, and
optimally with Conflict-Based Search.

- Page: `docs/index.html` (plain HTML + JavaScript, no dependencies, works offline)
- Data: `docs/data.js`, generated by the planner. Regenerate after changing the planner:
  ```
  ./build/swarmgrid export-demos docs/data.js
  ```
- Your own map: `swarmgrid export-plan <file.map> <file.scen> <numAgents> plan.json`, then
  "Open plan JSON" on the dashboard.
- Hosting: GitHub Pages serves the `docs/` folder of `main`
  (Settings → Pages → Deploy from a branch → `main` / `docs`).

### Robot control (interactive)

**https://tabish2786.github.io/SwarmGrid/control.html**: pick any of 10 robots, tap where it
should go (or where it should stand), and the whole fleet replans from where it is right now.

The planner on that page is this repo's C++ code compiled to WebAssembly, so it runs on the
visitor's device and gives exactly the native results (checked path by path against the native
build). Choose CBS (optimal; stops after 20,000 constraint-tree nodes), prioritized planning
(fast, collision-free, not optimal, can fail), or independent A* to see the collisions you get
without coordination.

- Page: `docs/control.html`; shared drawing code `docs/view.js`, shared styles `docs/style.css`
- C interface for the browser: `web/wasm_api.cpp`
- `docs/swarmgrid-planner.js` is generated. Rebuild it after changing the planner (needs
  [Emscripten](https://emscripten.org), tested with 3.1.74):
  ```
  source /path/to/emsdk/emsdk_env.sh
  ./web/build_wasm.sh
  ```

## Build

### Windows: Visual Studio 2022 (MSVC)
Install Visual Studio 2022 Community with the **Desktop development with C++** workload
(it ships with CMake). Open **Developer PowerShell for VS 2022**, then:

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
.\build\Release\swarmgrid.exe map data\maps\tiny-8x5.map data\scens\tiny-8x5.scen 3
```

### Linux / WSL2
```bash
sudo apt install build-essential cmake
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DSWARMGRID_SANITIZE=ON
cmake --build build -j
ctest --test-dir build --output-on-failure
./build/swarmgrid warehouse 10 42
```

CMake options: `SWARMGRID_BUILD_TESTS` (ON), `SWARMGRID_WERROR` (OFF), `SWARMGRID_SANITIZE` (OFF, GCC/Clang only).

## Layout

```
include/swarmgrid/   public headers (one per module)
src/                 implementations + main.cpp (CLI)
tests/               doctest unit tests, one file per module
docs/                web dashboard + robot control page (GitHub Pages)
web/                 WebAssembly interface + build script for the control page
third_party/doctest/ single-header test framework
data/maps, data/scens  MovingAI-format maps and scenarios
```

## Checking CBS

- Optimality: on 60 random small instances (and the corridor, goal-blocking and 4-robot
  intersection cases) CBS's sum of costs equals an independent brute-force optimum computed by
  Dijkstra over the joint state of all robots (`tests/test_cbs.cpp`).
- Every CBS plan in the tests and demos goes through the independent validator (`validatePlan`).
- `swarmgrid cbs-bench [timeLimitSeconds]` compares CBS with prioritized planning for 5 to 30
  robots on the generated warehouse (10 instances each). Times depend on the machine.

## Data

Benchmark maps and scenarios come from the [MovingAI MAPF benchmark](https://movingai.com/benchmarks/mapf.html).
`.scen` `optimal_length` values are octile (8-connected) distances, so they do **not** equal
4-connected shortest paths.
