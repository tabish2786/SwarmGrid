How to use

  1. Pick a robot above (or tap it on the map, or press 0–9).
  2. Send here: tap a free cell and the robot drives there; everyone else replans.
  3. Place robot puts it somewhere else; Edit shelves adds or removes a shelf.
  4. Start orders runs the warehouse on its own. Break down stops a robot and the others drive around it.
  5. Compare planners: CBS is optimal, ECBS stays within w of optimal and handles 50 robots, Prioritized is fastest, Independent A* shows what happens without coordination.
  6. Robots changes the fleet size; Assignment picks how parcels are handed out.

How it works

Every change reruns the project's C++ planner, compiled to WebAssembly, on your device, in a background Web Worker so the page never freezes (opened from a file, it runs on the page). CBS (Conflict-Based Search) finds the collision-free plan with the lowest total time: it plans each robot alone, finds a collision, and branches on which of the two robots has to avoid it. It first picks cardinal collisions (found with MDDs: every shortest path of both robots uses that cell) and bypasses branches that cost nothing, which cuts the search tree a lot. ECBS allows a plan up to w times the optimum and in return prefers paths that collide less, so it handles far more robots. Prioritized planning plans robots one by one: fast, not optimal, and it can fail on a solvable layout.

Orders go to robots by greedy nearest pair or by the optimal Hungarian assignment (both in C++, using true distances around shelves). The fleet replans whenever a robot picks up an order; if CBS or ECBS needs more than 0.4 s there, prioritized planning takes that replan. A broken robot is just a new shelf to the planner. If a planner fails, the page keeps the old plan and says why.

Planner: the project's C++17 code compiled to WebAssembly (web/build_wasm.sh). It runs in your browser; nothing is sent anywhere.
